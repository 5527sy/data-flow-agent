# 交互设计 · 卡片式向导流程（人机共驾）

> 版本：v0.1 ｜ 上游：《设计方案》《技术细节》《银行数据分析 Agent 完善流程》
> 核心理念：**机器负责算和画，人负责拍板和签字**。每张卡片 = 一次"系统提案 → 人工审批"。

---

## 1. 全局页面框架

```
┌────────────────────────────────────────────────────────────┐
│ 步骤导航条（Stepper）                                        │
│  ①需求路由 → ②样本设计 → ③取数上传 → ④数据体检               │
│  → ⑤清洗特征 → ⑥训练评估 → ⑦名单输出                         │
│  状态样式：✓已完成(绿) ▶当前(蓝) ○未到(灰) ⚠参数过期/打回(红)  │
├────────────────────────────────────────────────────────────┤
│ 当前步骤大卡片（滑入/滑出动画，一次只见一张）                   │
│  ┌──────────────────────────────────────┐                   │
│  │ ① 任务说明：这步干嘛、为什么要做        │                   │
│  │ ② 参数区：系统预填默认值，人工可改      │                   │
│  │ ③ 执行区：[运行] 按钮 + 进度条          │                   │
│  │ ④ 结果预览：图 + 指标 + 表格前 N 行     │                   │
│  │ ⑤ 决策区：[通过→下一步] [调参重跑] [打回上一步]             │
│  └──────────────────────────────────────┘                   │
├────────────────────────────────────────────────────────────┤
│ 底部：快照保存状态 ｜ 运行日志入口 ｜ 导出进度报告              │
└────────────────────────────────────────────────────────────┘
```

## 2. 每张卡片的统一五段结构

1. **任务说明**：这步干什么、对最终结果的影响（给非技术同事看的一句话）
2. **参数区**：**系统预填智能默认值**，人工只改不满意的项（不要全靠人填——人不知道填啥，也容易每次填得不一样）
3. **执行区**：点运行 → 进度反馈（长任务显示阶段日志）
4. **结果预览**：图 + 关键指标 + **一行"人话结论"**（如"共剔除 12 列缺失率>80%，剩 38 列，建议保留"——人扫一眼就能拍板，不用自己读图）
5. **决策区**：通过并下一步 / 调整参数重跑（本卡片内）/ 打回上一步（带上原因）

## 3. 七张卡片的参数与预览明细

| 卡片 | 人工决策/参数（默认值由系统预填） | 运行产物 | 结果预览 |
|---|---|---|---|
| ① 需求路由 | 确认分析范式（路由器给建议+理由）、指定目标列 | 范式判定书 | 判定理由卡片（双通道结论对照） |
| ② 样本设计 | 观察期/表现期时间窗口、正负标签定义、排除规则、预估样本量 | 《样本设计方案》+ SQL 脚本 | 样本时间轴示意图、预估正负比 |
| ③ 取数上传 | （线下取数后）上传文件、列映射确认 | dataset 登记 | 文件前 20 行预览 + 列清单 |
| ④ 数据体检 | 最小行数（默认 1 万）、正负比告警区间（默认 1:10~1:1000）、缺失率剔除上限（默认 80%）、单一值占比阈值 | 《数据体检报告》 | 缺失率条形图、正负样本饼图、各列分布直方图 |
| ⑤ 清洗特征 | 分箱方式（等频/等距/卡方/决策树，默认卡方）、WOE 单调性开关、**IV 阈值（默认 0.02）**、相关性去重阈值（默认 0.7）、缺失填充策略（默认中位数/众数） | 清洗后数据 + 特征保留清单 | 清洗前后对比图、**特征 IV 条形图（点开单特征看 WOE 曲线）**、保留/剔除特征明细表 |
| ⑥ 训练评估 | 勾选参与模型（LGB/LR/XGB）、CV 折数（默认 5）、不平衡策略（class_weight/SMOTE）、OOT 切分时间点、主评估指标（AUC/KS） | 训练好的模型 + 评估报告 | ROC/KS 曲线、特征重要度 Top20、三模型对比表、CV vs OOT 对比 |
| ⑦ 名单输出 | Top-N 或分数阈值二选一、分层切点、是否剔除存量客户（默认是） | 名单 Excel + 分析报告 | 名单前 100 行预览、分数分布图、预计响应人数 |

## 4. 六条全局机制（补充设计）

### 4.1 参数改动的"涟漪过期"
修改第⑤步的 IV 阈值 → 第⑥⑦步自动标记 **⚠️ 参数已过期，结果需重跑**。
原理：步骤间是依赖链，上游参数变了，下游旧结果一律视为失效，防止拿旧结论继续走。（技术：依赖传播的脏标记）

### 4.2 快照与回溯
每步运行结束自动存档：`outputs/run_{id}/step_{n}_v{版本}/`（参数快照 + 产物 + 图表）。
- 支持**回到任意步骤**重跑（不是只能回上一步）
- 支持**隔天继续**：刷新页面/重新登录后，从最近快照恢复现场

### 4.3 审计日志（银行刚需）
每一步记录：谁、什么时间、用了哪些参数、点了通过还是打回、LLM 给了什么建议。
两个用途：行内合规审计；面试讲"操作全程可审计可回放"。

### 4.4 人话结论生成
每个预览区顶部一行 LLM 生成的自然语言结论（只喂汇总指标，不喂行级数据）。
原则：**人只做判断题（同意/不同意），不做阅读理解题**。

### 4.5 失败与打回路径
- ④体检不合格 → 打回②（携带不合格原因：正负比太悬殊/行数不足），重新设计样本
- ⑥训练不满意 → 卡片内调参重跑，或回退到⑤改特征
- 任何一步都可以"带原因打回"，原因写入审计日志

### 4.6 卡片间只传"产物引用"，不传数据本体
下一步卡片引用的是上一步产物路径（dataset_id / 文件路径 / pipeline 对象），这与"清洗规则固化重放"呼应：⑤产出的 pipeline 就是⑥打分时的输入之一。

## 5. 技术映射（衔接现有技术栈）

| 交互元素 | 技术实现 |
|---|---|
| 步骤状态机 | 现有 session state 扩展：`current_step / step_status{n} / params{n} / artifacts{n} / dirty{≥n}` |
| 卡片切换 | 原型期 Gradio：Tabs + state 控制显隐（stepper 动画从简）；正式版 Vue3 stepper 组件 |
| 每步端点 | `POST /step/{n}/run`、`POST /step/{n}/confirm`、`GET /step/{n}/artifact` |
| 产物存储 | 本地目录按 run/step/版本分层（后续可换 MinIO） |
| LLM 用途 | 每步"人话结论" + 路由建议 + 样本设计建议；计算照旧全部外置 |
| 重算判定 | dirty 标记沿依赖链传播 |

## 6. 一句话总结（面试可直接用）

> "我把数据分析 Agent 的交互设计成**向导式人机共驾**：系统每一步给出带默认参数的提案和可视化结果，人只做三个动作——改参数、看预览、拍板；所有决策进审计日志，所有产物进版本快照，上游参数变更自动使下游结果过期。机器负责算和画，人负责拍板和签字。"
